# **1\. Introduction**

Munch Find\! is a simple little app for the moment your stomach's growling and your mind's gone blank — you set a budget, a cuisine, maybe a dietary need, and it just picks one store and one dish for you, no scrolling required. For groups, everyone joins a session and gets the same random pick together, so nobody has to be "the one who chose" and take the blame if it's a dud.

It's needed because every food app out there — GrabFood, Foodpanda, Google Maps — is built to show you more, not less, and that's exactly backwards for someone who's tired, hungry, and just can't decide. This one flips the whole idea: instead of adding choices, it takes the choice away, which is often the kindest thing an app can do.

## **Functional Requirements**

**FR-001 Random Selection | from: Q1 Survey**  
 The system shall randomly select one store and one dish from an available dataset when the user requests a decision.

**FR-002 Filter Application | from: Q1 Survey**  
 The system shall allow the user to set at least one filter (budget, cuisine, or dietary restriction) before the random selection is generated, and shall apply that filter to constrain the result.

**FR-003 Result Display | from: Q1 Survey**  
 The system shall display the selected store name and dish clearly to the user immediately after selection, without requiring further navigation.

**FR-004 Group Mode Session  | from: Q1 Survey**  
 The system shall allow two or more users to join a shared session and shall display the same randomly selected result to all participants in that session.

## **Non-Functional Requirements**

**NFR-001 — Easy-to-understand interface | Usability**  
 The system shall allow a first-time user to reach a final food decision (from opening the app to seeing a result) in under 1 minute, without needing instructions.

**NFR-002 — Low latency and loading times | Performance**  
 The system shall generate and display a random result within 3 seconds of the user's request, under normal prototype testing conditions.

## **Desirable Requirements**

**OPT-001 — Re-Roll Option | from: Q6 Survey**  
 The system could allow the user to reject a result and request a new random selection, up to a limited number of times per session.

**OPT-002 — Location-Based Filtering | from: Q4 Survey**  
 The system could filter store selection based on the user's current location or a distance radius, to prioritise nearby options.

## **Possible Future Enhancement**

**FE-001 — Order History & Preference Learning | planned for: V1.2**  
 Future versions could track a user's past selections and gradually weight randomisation toward cuisines the user tends to accept, rather than pure uniform randomness, improving relevance over time without removing the core "decision made for you" experience.	

## **Constraints**

**C-001 — Real payment processing or actual food ordering/checkout | Budget, Technical**  
Payment processing has a tax on each transaction. Ordering food requires all merchants and restaurants to adopt the app or partner with an external company (ex. Grab, FoodPanda) for their api which is costly and requires negotiation.

**C-002 — Real-time integration with actual restaurant menus, pricing, or live stock/availability | Budget, Technical**  
Restaurants would have to update their stock every time which can be time consuming and will cause errors like “The cake is there why does it say it's sold out on the app” or an item being unavailable but still ordered. Again, partnering with another company is an option but a difficult one

# **5\. Conclusion**

This app saves people from the exhausting work of deciding, by simply deciding for them. It cuts **decision fatigue, group deadlock, keeps results relevant, not random noise and fills a real gap.**  no scrolling through endless menus and listings, just one clear answer in under a minute. Everyone joins a session, gets the same random result, and commits to it together, so no one person carries the blame for a bad pick. Filters for budget, cuisine, and dietary needs mean the pick still fits real constraints, it just skips the browsing. Existing platforms (GrabFood, Foodpanda, Google Maps) are all built to maximize browsing, not minimize it, so there's genuinely no widely-used tool doing what this does.
